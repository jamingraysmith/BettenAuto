# Automatic public dealer comparisons

The public collector is the default low-cost market path. It makes **no Auto.dev calls**, incurs no market-provider subscription or per-VIN fee, and shares source snapshots across all present and subsequently imported vehicles. Hosting, maintenance and scheduled task usage are separate costs. It is a selected public asking-price sample, not vAuto's licensed market dataset or a sold-price valuation.

## Unattended operation

The published owner-private Site exposes:

- `GET /api/public-market/status`: saved source health, counts, true observation times and strict inventory match coverage. This read never collects listings.
- `POST /api/public-market/refresh` with `{"limit":2}`: processes at most **one** due source per request from the fixed server registry. The requested limit remains a ceiling. Repeat until `processed` is zero, at most **200 batches**; stop sooner when no work remains. An empty body must be `{}`. Caller-supplied URLs are rejected. A complete source with no pending detail checks becomes eligible at the next **9:00 AM America/Detroit** window, including daylight-saving changes. Errors become eligible after at least one hour; the schedule determines the actual next attempt. Pending bounded detail passes remain immediately eligible until their queue is checked.
- `GET /api/workspace`: read back merged public snapshots and preserved dealership records. Inventory and appraisal screens recalculate from this shared library. Browser reads refresh once a minute and on focus without clearing edits.

The Sites cloud task must obtain this Site's existing private service credential through the supported Sites tools and send it only as `OAI-Sites-Authorization: Bearer <credential>` to the exact published Site origin. Never put it in a URL, file, log, message, source or automation prompt. Do not use a signed-in browser or a local computer as the scheduled source path. The standalone `ops/run-public-market-refresh.mjs` accepts the same credential through hidden stdin for operator verification.

The requested daily start is **9:00 AM Eastern**, with collection completing afterward as pages are verified. This is a start window, not a promise that every website finishes at exactly 9:00. Source delays and failures remain visible. Confirm the actual saved task schedule and completion readback; changing source eligibility alone does not change a scheduler. Scheduled runs update data directly, with no build or redeployment. They must preserve the current owner-private audience, make no paid provider searches, never publish vehicle prices, and stay quiet unless collection fails, coverage materially changes, or user action is required. The existing local browser import may continue refreshing inventory and sources which reject unattended HTTP; its browser-only observations keep their own dates.

## Source policy and correctness

`lib/public-market-sources.ts` is the reviewed first-party URL registry. It contains shared New/Used feeds, not a hardcoded subject VIN or comparable set. Add sources only after verifying ordinary server HTTP, robots instructions, structured asking prices, exact condition/make coverage, complete pagination and dealership identity. Do not follow a blocked private upstream feed, bypass an HTTP denial, execute source JavaScript, or silently use analytics MSRP as selling price.

Every source request uses the collector's own identity and checks the source's robots policy. Redirects, cross-origin pagination, changed totals, incomplete sets and oversized responses fail closed. JSON-LD and literal Dealer.com `DDC.WS.state['ws-inv-data']` JSON are parsed as data; no source JavaScript runs. Dealer.com pagination follows its observed next-page link, and each page supplies its own account-to-rooftop mapping. A fee-only `totalFees` row cannot become a vehicle asking price. HTML and raw response bodies are not saved in the production database. VIN-linked visible headings preserve full advertised trim details when structured data abbreviates them. VIN-linked mileage, engine and drivetrain fields can supplement structured data. Unknown mileage, certification or vehicle variant stays unknown. An arbitrary group footer address is never treated as a vehicle's rooftop location. Cash asking prices can contain fees or conditional discounts; the UI shows their basis and makes no equipment, certification, mileage or incentive value adjustment.

Selected JSON-LD Volvo and Mercedes-Benz sources can make at most **12 public detail-page checks per pass** after complete result-page verification. Same-VIN detail evidence may fill missing trim, drivetrain, engine, body, mileage or advertised certification; it never replaces the verified result-page asking price. Retained metadata requires the same listing identity and keeps its original per-field observation dates. Failed or unresolved detail checks are throttled for 24 hours, so a daily run terminates rather than repeatedly fetching the same missing field. Known contradictions remain unresolved rather than overwriting source evidence.

Only a complete, internally consistent source snapshot can retire older observations for that same source path. Failures retain the last successful snapshot with its original timestamp and a visible error. A SQL lease prevents overlapping runners or late responses from overwriting newer work. Manual comparables, dealership costs, notes, recon, price plans and unrelated source observations remain independent. Normal backup exports exclude collector system records. Licensed Auto.dev results remain in their separate evaluation/cache rules.

`matchComparables` applies the same strict model/variant, year, trim, condition, certification, mileage and age rules in inventory, appraisals and coverage counts. No matches means insufficient sample. At least three valid asking prices are required for a sample percentage, rank or list suggestion. Collection breadth does not guarantee that every dealership vehicle has an eligible comparison.

# Browser fallback for reviewed sources

The desktop 9:00 AM Eastern refresh also reads normal public browser pages when an unattended request is denied. This requires the computer and Codex to be available. Browser access does not authorize bypassing warnings, CAPTCHAs or source restrictions. Some sources still cannot be verified; keep their last complete observations and dates.

Save new captures under a dated directory, with one subdirectory per exact registry source ID. Each page JSON contains `url`, actual UTC `observedAt`, and either literal public `WIS` plus `nextHref`, or observed HTML fragments in `htmlParts` plus `nextHref`. Read a fresh browser state after each navigation. Follow the observed next link and save all pages. Keep fragments below the browser tool's string limit; reject clipped content. Never execute page scripts or extract hidden application globals.

`ops/normalize-public-captures.mjs --dir ABSOLUTE_CAPTURE_DIRECTORY --out NEW_ABSOLUTE_OUTPUT_DIRECTORY` uses the shared public parser. It requires a consistent advertised total, complete observed pagination, valid unique VINs, contiguous Dealer.com offsets and actual ordered observation times. Its 100-page browser bound is independent of the smaller hosted request bound. It excludes wholesale only after validating source completeness. Failed sources contribute no replacement records and require retaining the prior dataset. Its output is a verified subset, not a full-market snapshot.

Use `ops/audit-public-market.mjs` to save the current hosted public aggregate, then `ops/assemble-market-snapshot.mjs` to combine it with verified browser bundles and the expanded sample. The assembler's configuration lists the base public listing file, comparison/report pairs, and expanded sample file. It replaces only verified complete sources and retains all other observations with their original dates. Publish the resulting aggregate through `ops/push-import.mjs`; never submit a browser subset as `complete=true`. Verify hosted VIN coverage and private record preservation afterward. Source health describes unattended collection; fresh browser-imported observations can also be present in the shared library.

### Retiring a VIN after a verified browser refresh

A complete `complete_selected_source_aggregate` import can exclude an older automatic listing when its VIN is absent from the full imported VIN set and the report proves that exact reviewed source was collected completely. The saved source ID, exact configured URL, counts and observation cutoff must validate. Failed sources and automatic observations newer than that source cutoff remain available; missing or invalid reports cannot retire automatic listings. This prevents a stale automatic snapshot from reviving a VIN removed by a newer complete browser capture. It does not reconcile which historical source remains valid when the same VIN survives in the aggregate through another dealer observation; that requires an explicit per-source VIN roster. Internal dealership records are unaffected.
