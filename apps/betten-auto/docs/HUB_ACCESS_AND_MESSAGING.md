# Standalone Betten Hub and access boundaries

The central Hub has a separate publication at https://betten-hub.roundlake4.chatgpt.site/. The Inventory Desk remains at its original URL and opens on its summary dashboard. The Hub launches applications separately; it does not embed the Inventory Desk. Native customer records and shared information start empty for staff entry. External application shortcuts do not grant access inside third-party applications.

Inventory Desk D1 remains the shared authority for permissions, departments, messaging, customers and Hub information. The Hub frontend does not receive a copy of inventory costs or the service credential. Its server signs an authenticated visitor email, fixed action, method, query, body, timestamp and random nonce using HMAC-SHA256. The receiving gateway verifies the signature and a 60-second clock window, rejects replayed nonces and resolves permissions from its own database. No request body can grant owner status, assign a department or replace the authenticated visitor email. Runtime credentials are kept in secret environment bindings and are never sent to browser code.

The owner identity is pinned server-side to the verified Sites owner email. Transferring ownership requires a deliberate server configuration change. New invited visitors have pending, deny-by-default permissions. Only the owner may approve, suspend, assign departments or change permissions. Module permissions are none, view or edit. Financial metadata is redacted from workspace responses without financial access. Partial vehicle updates preserve hidden fields and reject unauthorized changes. Full backups, financial imports, vehicle audit history and deletion remain owner-only. Permissions apply to every new API request; browser data already seen cannot be remotely erased.

Every active staff account has an assigned department. General is the default; the owner may create named departments and matching channels. Team Chat is visible to everyone granted messaging access. Department channels require current department membership; the dealership owner may access department channels. Direct conversations require participant membership, including for the owner. Staff cannot set their sender ID or department label. Department labels are captured when a message is sent. Changing a department revokes access to the previous department channel on subsequent requests.

Customer records require a separate customer permission. Customer attachment IDs are verified on send and redacted for recipients lacking customer access. Messages link to inventory VINs and customer IDs. They do not automatically import VinSolutions records. Staff should choose appropriate participants/channels before typing customer information. Stored messages are not end-to-end encrypted. Hosting administration and data backups must remain restricted to authorized administrators. No customer/employee roster or messages were copied from screenshots.

Existing message contents and IDs are retained when migrating a visitor's Site-specific ID to a canonical email identity. Legacy direct memberships are migrated transactionally and existing conversations are reused. Browser polling makes new messages visible while a signed-in app is open; there are no email, SMS or push alerts.

Site sharing remains a separate outer gate. An employee needs a Site invitation and matching application permissions. Creating an application user does not send an invitation. The new Hub starts owner-private; the existing Inventory Desk audience is preserved. The existing private Site's service credential remains privileged for authorized inventory automation; never make either backend public without redesigning that trust boundary.
